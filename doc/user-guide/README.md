# GNC 仿真框架用户指南

本指南基于当前仓库中的实际代码、示例、模板、测试和运行入口编写，目标不是把源码翻译成自然语言，而是帮助用户从“会编译运行”走到“能理解设计、能做自定义扩展、能搭建自己的仿真模型”。

这套指南覆盖的是当前仓库中的有效实现。`doc/architecture.md` 属于旧版架构说明，不再作为本指南依据。

## 这套框架是什么

这是一套以 C++17 和 Eigen3 为基础、以头文件为主的 GNC 仿真框架。它的核心思想不是把所有模型硬编码到一个主程序里，而是把系统拆成：

- 由接口定义职责边界
- 由组件封装具体实现
- 由 JSON 任务文件决定如何装配
- 由仿真器统一调度执行
- 由可观测字段系统统一记录输出

换句话说，这个框架更像一个“配置驱动的仿真底座”，而不是一个只支持少数固定模型的单体程序。

## 适合谁读

- 想快速跑通仓库现有示例的用户
- 想基于现有框架搭建自己的飞行器/制导/导航/动力学模型的开发者
- 想理解当前框架代码结构、接口分层和扩展方式的维护者

## 读完后你应该能做到

- 理解框架为什么采用“接口 + 组件 + 配置”的组织方式
- 知道一次仿真是如何从 JSON 构建出来并按频率调度执行的
- 知道内建组件能直接做什么，哪些能力还需要自己补充
- 能在 `user/components/` 下新增自己的组件而不改入口程序
- 能写自己的 mission 配置，控制仿真参数、组件装配、停止条件和输出字段
- 能把示例模型改造成自己的工程起点

## 框架的一句话设计概括

当前框架把“求解器、调度器、组件注册、依赖注入、数据记录”这些通用基础设施固化下来，把“动力学、环境、导航、制导、控制、传感器”这些领域逻辑开放给用户用接口扩展。

## 当前版本边界

当前代码已经具备很好的扩展骨架，但它仍然更偏“可扩展仿真框架”而不是“现成的全物理平台”。使用时应注意：

- 内建输出格式目前只有 CSV
- 停止条件目前只支持“某个可观测字段高于/低于阈值”
- 服务系统目前只实装了坐标服务，且现有示例中并未大规模使用
- 单车、环境、多飞行器的装配骨架已经具备，但仓库示例主要集中在单车场景
- `Wgs84Earth` 的大地坐标转换实现是简化版，不是高精度大地测量实现
- `IdealImu` 当前更接近“真值透传骨架”，并未提供完整的理想加速度求解与噪声建模
- `SimpleNavigation` 是占位/基础导航实现，主要用于串联流程，不是完整导航解算器

这些边界不是缺陷本身，而是说明框架的重点放在了“可扩展性与装配机制”，而不是替用户预置所有业务模型。
